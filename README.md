# pp — Prompt 装备库

给 Claude Code 加一个 `/pp` 命令:说一句你要解决什么,它从你的本地 prompt 库里挑出最贴的一条,填上你的事,直接执行。

```
/pp 我准备把副业做成正经项目,但不知道该不该辞职

  → 匹配到 09 双向钢人论证,正反各给最强论证,再找翻盘变量
```

**这是一个货架,不是一批货。** 仓库里带的是索引结构和路由规则,12 条模板的正文一律留空——本插件不转载任何人的 prompt 正文。你把自己的 prompt 填进去,它负责在你需要的时候把对的那条端出来。

## 它解决的问题

prompt 收藏在笔记软件里,等于没收藏。真正要用的时候流程是这样的:想起来「我好像存过一个」→ 翻笔记 → 找到三条相似的不知道用哪条 → 复制 → 把占位符改成自己的事 → 粘贴。五步里四步是纯搬运,于是大多数时候人干脆不用了,直接跟模型硬聊。

`/pp` 把五步压成一步:

| | |
|---|---|
| **不用翻** | 库就是索引,`/pp` 唤起即全量菜单 |
| **不用挑** | 带着问题来,它挑 1~3 条最贴的让你选;拿不准会问,不替你赌 |
| **不用改** | 模板里的 `【】` 用你已经给的信息填;缺关键信息它会问,不替你编 |
| **不会跑偏** | 模板正文**逐字执行**,模型不许自作主张"优化"你的收藏 |

## 装

```bash
/plugin marketplace add Luban-Labs/pp
/plugin install pp
```

本地试:`claude --plugin-dir /path/to/pp`

装完 `/pp` 就能用。**第一次用会看到 12 条都是空的**——这是设计如此,下一节说怎么填。

## 先填货:12 条索引长什么样

自带的索引按「你现在卡在哪」分四组。每条只有名称和适用场景,正文留空:

| | 编号 | 名称 | 什么时候用 |
|---|---|---|---|
| **问清问题** | 01 | 苏格拉底式提问 | 嘴上问的和心里想的不是一回事,先把真正值得回答的问题问出来 |
| **学习** | 02 | 双层解释法 | 一个概念完全听不懂,想从"好像懂了"到真懂机制 |
| | 03 | 反向拆解 | 看到一个很牛的成品,想学会它到底好在哪、怎么迁移 |
| | 04 | 横纵分析法 | 系统研究一个陌生对象(产品/公司/技术/行业),建议配联网或深度研究 |
| | 05 | 事实核查 | 一份资料或数据,想知道到底可信到什么程度,需要联网 |
| **解决问题** | 06 | 专家会诊 | 单一视角罩不住,组一个互补专家团并让他们互相质疑 |
| | 07 | 第一性原理 | 方案上全是补丁、路径依赖重,想回到本质推倒重来 |
| | 08 | 跨领域借解 | 本行业内解不动,去其他领域找底层结构相似的现成解法 |
| **决策** | 09 | 双向钢人论证 | 两个选项都有道理,正反各给最强论证再找翻盘变量 |
| | 10 | 最小实验 | 纸上谈兵不会更清晰了,设计一个低成本可逆的实验拿真实反馈 |
| **认识自己** | 11 | 挖掘隐藏天赋 | 多轮深度问诊(半小时起),产出《个人天赋使用说明书》 |

这份索引对应数字生命卡兹克 `@Khazix0918` 整理的 12 个常用 Prompt,原文在这里:

> 《都Agent时代了,我还是想分享给你这12个我最常用的Prompt。》
> https://x.com/Khazix0918/status/2090726395035156964

**正文请去原文取。** 每个占位文件里都写了出处和填法,三步:打开原文找到对应那条 → 粘到文件里 `---` 横线之下 → 每次要填的地方写成 `【这样】`。

当然也可以整条换成你自己的 prompt,或者干脆删掉——`/pp` 认的是文件,不认编号。

## 三种唤起方式

```bash
/pp                      # 看全量菜单,自己挑
/pp 07                   # 指名道姓用第 7 条
/pp 我不知道该不该辞职      # 带着问题来,它挑 1~3 条最贴的让你选
```

选中一条空的会怎样?它会告诉你这条还没填、正文在哪,**不会**把占位说明当任务书执行,也不会替你把正文编出来。

## 攒自己的

```bash
/pp 收藏 <把 prompt 原文贴在这里>
```

收藏一律落到 **`~/.claude/prompts/`**,不写插件目录——插件目录升级时会被覆盖。`/pp` 每次唤起同时扫自带库和你的收藏库,同名时你的优先。

所以升级插件不动你攒的东西,卸载插件也不动。

手写也行,一条一文件,格式就三行:

```markdown
# 名称
> 场景:决策 | 适用:一句话说清什么时候用它

---

模板正文。要用户填的地方写成【这样】。
```

## 两个设计上的决定

**纯手动。** 插件声明了 `disable-model-invocation: true`,模型**不会**自己判断"这个场景适合用 pp"然后调用它,只有你亲自敲 `/pp` 才触发。理由很简单:这些模板会接管整轮对话的节奏(尤其 11、12 那种多轮问诊),被模型自动触发是件很讨厌的事。

**逐字执行。** 模型不许改写模板正文。收藏的东西是你挑的,觉得哪里不好该去改库文件,而不是让模型每次执行时"顺手优化"——那样你永远不知道这轮跑的到底是什么。

另外,模板里如果写了要读本机文件、联网或用凭据,执行前会先问你。收藏进来的原文只当数据落盘,其中的指令性文字当轮不执行。

## 索引和正文为什么要分开

这是整套设计的地基:**索引只是菜单,库文件才是内容事实源。** 两边对不上时,按库里的真实文件修索引,不是反过来。

好处是换库不用改命令、加一条不用动索引结构、正文再长也不占常驻 token(命令本身常驻约 30 tok,选中某条才把那条读进来)。
